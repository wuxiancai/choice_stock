# Handoff

## 当前状态

第一版已实现：可本地启动、可由 systemd 托管的 A 股盘后选股与行业资金流看板。`deploy.sh` 会自动检测 Python 3.12+；macOS 缺少时通过 Homebrew 安装，Ubuntu 缺少时通过 apt（必要时 deadsnakes PPA）安装，再创建 `.venv` 与安装全部项目依赖。

技术信号表现已覆盖量比、换手率、成交额、总市值、PE、PB 与涨跌幅；筛选仅保留评分、九转、主力净流入、量比、换手率、成交额、总市值、PE、PB 的最小/最大值组合。MACD、KDJ、RSI、布林位置和涨跌幅仍展示及支持表头排序，但不再作为筛选条件。估值与量比来自 Tushare `daily_basic`；当前数据库中的历史信号需在下一次同步后重新计算才会填充新增字段，数据源无权限或缺值时页面显示 `—`。

`20260814` 修复了新增字段迁移后旧信号的 `pct_chg=NULL` 导致首页模板比较 `NULL >= 0` 并返回 500 的问题；页面会把该类历史缺值显示为 `—`。

`20260814` 行业板块固定标为最近 5 个交易日，并按每个交易日的涨跌幅增加名次；主力净流入使用红色、净流出使用绿色，金额统一显示为 `亿` 或 `万`。当日技术信号中的成交额（Tushare 千元）、总市值（Tushare 万元）和主力净流入（元）均已按实际人民币金额格式化；九转改为正数 Sell、负数 Buy，只有第 8/9 转才显示对应的红/绿信号。历史板块数据仍必须由支持指定交易日的数据源真实回补，当前公开降级源仅能提供当日数据，不能伪造为历史快照。

`20260814` 修复行业五日矩阵仅有最新日快照的缺陷：首次同步会在写入当日板块快照后，逐行业通过东方财富历史资金流与历史行情接口回填缺失的前四个交易日；历史接口缺失时不复制当日数据。日期列显示每日涨跌幅排名；“5 日净流入/涨幅”改为五日数据的算术平均值，并且只有五天完整快照时展示。技术信号的涨跌幅、主力净流入已移至 MACD 前。行业板块和当日技术信号表均默认显示 10 行，保留表头并在表内滚动查看其余结果。

`20260814` 若 Tushare/东方财富探测失败但备用 `ths` 已返回完整行业数据，同步仍视为成功；实际数据源记录在 `sync_runs.source`，前置探测失败不再显示为用户可见错误。行业矩阵的五个表头改为根据已同步日线的最近五个交易日生成，因此即使板块历史回填尚未完成，也会固定显示五个日期，并以 `—` 明确标出缺失排名。

`20260815` 行业矩阵按最新交易日涨幅从高到低排序，第二、三列固定为当日涨幅和当日净流入；日期列保留对应交易日的涨幅排名。九转展示不再隐藏第 1–7 转，因此筛选区间 `4–5` 的结果会显示 `4` 或 `5`。东方财富历史回填先单次预热行业代码映射、再限为 3 路并发，避免并发重复映射请求造成 502；若历史接口仍不可用，只向页面显示一条包含失败行业数量的摘要，而不展示逐行业 URL 错误。当日 `ths` 数据已成功时不受历史回填失败影响。

`20260815` 所有页面日期统一为 `YYYY-MM-DD`，日志时间统一显示为上海时区 `YYYY-MM-DD HH:MM:SS`。九转列仅显示数字：正数（上涨/Sell）红色，负数（下跌/Buy）绿色并以绝对值显示。行业资金流真实备用顺序为 Tushare 同花顺、Tushare 东方财富、东方财富、同花顺、腾讯。腾讯源已接入：拉取全市场实时股票的涨跌幅与主力净流入，并按 Tushare 股票行业分类加权聚合成当日行业快照；它不能替代东方财富的历史行业回填。新浪未接入。所有来源失败时错误文案会压缩为每个来源的简短状态，不显示权限 URL 或原始响应。

`20260815` 修复“立即同步”未补齐历史行业快照的问题：此前只要某日期存在任意一条板块记录便跳过，残缺的历史日期因而不会重试；现在日线与行业快照均以有效行数判定完整，缺失或残缺日期才会被增量回补，完整历史不会重复拉取。页面的“实际已同步”也只计完整快照日。技术信号筛选移除评分、总市值（表格仍展示）；九转列移至评分后第 3 列；标题和数据健康状态在桌面端同一行，窄屏自动纵向排列。

页面最后新增“系统日志”：`sync_latest` 失败、行业资金流降级和页面/API 未处理异常会写入 SQLite `system_logs`，展示最近 50 条 ERROR（UTC 时间）；记录中的 Tushare Token 会脱敏。

当日技术信号表支持浏览器端点击表头排序（再次点击反向；`—` 缺失值始终在末尾），不改变后端筛选或需要重新同步。
